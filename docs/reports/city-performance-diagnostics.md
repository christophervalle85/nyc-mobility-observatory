# City interaction and loading diagnostics

Baseline checkpoint: `595936f`. Scope: investigate initial loading, selection feedback and the angular floating-city edge. No actual browser timings are inferred from CPU microbenchmarks.

## Evidence before optimization

On this Mac (Apple M4, Node 23.11, arm64), the official TLC source is 3,871,294 bytes, 263 areas, 354 polygon parts and 98,192 vertices. A repeated Node benchmark found:

| Operation | Median | p95 |
| --- | ---: | ---: |
| JSON parsing | 14.37 ms | 15.53 ms |
| Build area picker | 0.54 ms | 0.64 ms |
| Pick an area | 0.005 ms | 0.005 ms |
| Construct borough convex hulls | 43.82 ms | 49.84 ms |
| Selection helpers excluding DOM/GPU | 0.049 ms | 0.052 ms |
| Construct 354 Cesium entities (CPU only) | 13.34 ms | 14.56 ms |

These results exclude browser JavaScript compilation, DOM work, terrain/3D clamping, GPU work, tile delivery and image decoding. They do not establish a cold start or user-device FPS.

Source inspection identified a feedback gate: camera movement clears/hides selection until Cesium reports every tile required by the current screen-space-error threshold loaded, with camera and focus stopped. The explicit focus action also includes a deliberate 1.2-second flight. These delays must be measured separately from hit testing. Selector options are rebuilt on each selection.

## Boundary source

The original cutout uses convex hulls of TLC zones. This connects concavities across water and produces straight artificial edges; performance settings cannot turn the hull into a coastline.

NYC DCP's official `gthc-hcne` Borough Boundaries dataset explicitly excludes water. Live metadata identifies version 26c, updated November 2, 2026. The captured GeoJSON has five MultiPolygon features, 117 outer parts and one hole. It is a separate display source, not a replacement for TLC area identifiers/data joins.

Source: https://data.cityofnewyork.us/City-Government/Borough-Boundaries/gthc-hcne/data

Raw export SHA-256: `9677a5c0e497105e4375e7253d157a9027134514ac92bcfca207e4c55631519b`; 3,167,508 bytes. Frozen source and metadata are local in `.data/land-footprint/`; derived asset/provenance will record any generalization. No alignment with Google's imagery date is assumed.

## Browser measurement protocol

Use explicit `?diagnostics=1`, fixed numeric-only labels, bounded observers and existing render events. Distinguish geography parsing, Cesium import/runtime work, tile metadata, first tile-bearing frame, fully settled detail, selection handler time and next actual scene render. Never log resource URLs, request bodies, credentials or raw provider errors. No extra rendering or provider requests are generated by profiling.

Comparison must use the same browser, viewport and interaction sequence. Cache/network state is not controlled unless stated; an ordinary reload is not a certified cold-cache run. CPU scene-render wall time is not a GPU timestamp or universal FPS measurement.

## Cleanup result and release decision

The artifact-only cleanup keeps every 88 outer-coordinate array and the genuine water-hole array bit-for-bit identical to the full candidate. It removes42 hole descendants traced to microscopic raw-union slivers (not an output-area filter: topology-preserving simplification had enlarged some slivers). Current220,409-byte asset has88 components,1 hole and5546 positions; hash`467451004dedbeabfa446bde4cfb011b68c9276db83e0ca2c30fafb46560bf19`.

At the same verified1440×900 viewport, the cleaned trial measured867.5 ms to firsttile-bearing frame,6129.7 ms to settled detail, mean/max CPU render11.67/367.60 ms, and13 startup long tasks totaling3544 ms. It improved over the full candidate but remained substantially worse than the 2032.4 ms hull control. This does not isolate GPU time or prove a universal3× network slowdown. The detailed land mask is **not promoted to default**. It remains available through`?cutout=land` for explicit review. Default imagery/clipping quality settings are unchanged.

Responsiveness changes are retained: the selected outline is independent of full-detail readiness, fill remains gated, and unchanged-query selection reuses native option nodes. Live inspection showed the outline still present while the Focus action was in progress. One warm postfix selection measured1.1 ms handler,0 ms rounded option-update duration and14.3 ms to the next scene frame. This is not an INP score or guarantee of ground-clamped pixel latency.

## Remaining limits

- Initial load is still dependent on imagery delivery, decode/processing and device/browser rendering. No certified cold-cache Chrome profile, GPU timestamp or representative low-end-device benchmark was completed.
- The default retains angular TLC hulls. A performant natural floating edge remains unresolved; the detailed optional preview trades additional processing for a better contour. Further improvement should revisit mask complexity or rendering architecture, not blindly lower imagery quality.
- DCP land is generalized administrative data, not exact contemporary shoreline or a solid extracted floating mesh. The sampled geometric deviation audit uses the explicitly normalized baseline after numerical-hole cleanup.

Separate architect/frontend/QA/geometry/reviewer workers applied the saved role instructions. Native local CLI profile invocation remained unavailable because its configured model was rejected; this work used delegated workers with those instructions. No credentials were read. No merge, push or deployment is part of this pass.
